# CAN tests

## 引脚与测试条件

依据 `hardware.md`：CAN1 RX=PA11、TX=PA12，经 P10 跳线选择，与同引脚的 USB OTG 数据线互斥。工程 overlay 已替换评估板的 PD0/PD1 配置，并按 STM32H743IIT6 pinctrl 核对 AF9。

本固件将 PA11/PA12 配置为 CAN，P10 应切到 CAN 一侧，停止使用共享数据引脚的 USB OTG 接口；这不影响 USART1 PA9/PA10 的 USB 转串口管理连接。软件不能判断跳线位置，也不能替代接线核对。

FDCAN 内核时钟显式选择现有 25MHz HSE，分频 1；不沿用评估板 PLL2 配置。500kbit/s 是内部回环测试默认值，不代表硬件文档规定了板端总线速率。实际 HSE、位时序和外部通信速率必须实板确认。

只支持经典 CAN 2.0，8 字节以内，不启用 CAN FD/BRS。内部回环不需要外部 CAN 对端；外部测试需要 CAN 收发器、正确 P10 跳线、共地、适当的两端终端电阻和相同波特率的有效对端。不能把 MCU TX/RX 直接接到 CAN_H/CAN_L。

## 命令

USART1 Shell 仍使用 115200、8N1：

```text
fct run can-loopback
fct results

fct can tx 500000 std 0x123 0102030405060708
fct can tx 500000 ext 0x18ff1234 -
fct can rx 500000 std 0x123 3000
fct can rx 500000 ext 0x18ff1234 3000
fct stop
```

- `std` 为 11 位 ID，范围 0..0x7ff；`ext` 为 29 位 ID，范围 0..0x1fffffff。数字可用十进制或 `0x` 前缀。
- TX 数据为不带空格、不带 `0x` 的偶数个十六进制字符，最多 16 个；`-` 表示零长度数据帧，不是 RTR。
- 波特率需显式指定，范围 10000..1000000 bit/s，具体可实现性由驱动位时序计算决定。
- RX 等待时间 10..5000ms；TX 完成等待固定 1000ms。参数错误不会提交测试任务。
- 外部测试不会由 `fct run all` 执行；直接 `fct run can-tx/can-rx` 会拒绝，必须通过带完整参数的命令启动。

## 判定范围

| 项目 | 通过条件 | 不证明的内容 |
|---|---|---|
| `can-loopback` | 内部回环各发送一条标准/扩展 8 字节帧，确认 TX 完成、接收 ID/格式/长度/完整载荷及控制器健康状态 | PA11/PA12 电气连接、P10、收发器、终端电阻和外部总线 |
| `can-tx` | 正常模式发送完成且有对端 ACK，控制器保持 error-active | 对端应用已经接收或解析了正确载荷；需要对端抓包进一步确认 |
| `can-rx` | 正常模式收到指定 ID 与格式的数据帧，打印载荷，控制器保持 error-active | 帧来源身份、所有总线节点或板端完整 TX 数据通路 |

内部模式使用 Zephyr M_CAN 的 `LOOPBACK | LISTENONLY` 组合，对应内部回环，不向物理总线输出测试数据帧；每条测试载荷包含变化序号，旧回环帧不能被当作新载荷通过。FCT 的 `all` 包含此软件选择的控制器内部测试。

外部 RX 使用正常模式，会参与 ACK，不是被动监听。RX 只接受与指定 ID/格式匹配的数据帧，RTR 或同 ID 的另一种帧格式不能让测试通过。TX 没有 ACK 时可能自动重发，应用等待到期后会停止控制器并取消待发送帧；发送入队成功本身不能标为 PASS。

正常完成、超时、取消和失败均停止控制器、移除本次过滤器；清理失败会打印且不能把原本成功的测试记为 PASS。停止会保留配置但不继续参与总线；下一次测试重新配置速率与模式。

日志中的停止前状态使用 HAL 枚举：0=error-active，1=error-passive，2=bus-off，3=stopped，4=error-warning。软件检测到错误并报告失败，不表示已经完成电气故障注入验证。

## 抽象层与回调

新增 HAL 控制器配置、启动、停止接口，以及 STOPPED/WARNING 状态。配置只允许在停止时修改，成功停止会同步取消本后端的待发送项。旧错误状态枚举数值保持不变。

真实后端使用固定 8 个 TX 上下文与 4 个逻辑 RX 过滤器。逻辑过滤器保持原契约的数值 ID/掩码语义，同时注册适用的标准与扩展原生过滤器；第二个安装失败时回滚第一个。公共过滤器 ID 使用递增 token，拒绝重复移除和旧 token。

TX 始终走异步驱动，即使应用未提供完成回调，也不会误选原生的阻塞发送。TX 排队等待限制为 0..1000ms；测试实际使用 20ms，完成等待另算，避免无限排队阻塞停止操作。原生 `-EAGAIN` 转成超时，错误及停止取消均释放 TX 上下文。

回调可能发生在 ISR，或在停止任务内同步发生。FCT 回调只在 OSAL 短临界区中更新静态事件，不调用阻塞同步接口、动态内存或 Shell；工作任务每 10ms 检查事件、取消和超时。所有回调对象具有静态生命周期，不引用测试栈变量。清理先关闭事件接收，再停止/移除，避免迟到完成影响已结束的结果。

离线 Zephyr/Linux 后端为新增生命周期接口返回不支持。USB stack 与此 CAN 固件同时启用会触发构建检查；未来需要 USB 测试时，应设计单独配置或受控引脚切换，不能直接同时启用。

## 验证情况

- 真实 Zephyr 固件编译链接；检查最终 DTS 的 PA11/PA12、HSE 时钟和 CAN FD 关闭配置；启动地址保持 `0x08000000`。
- 主机 FCT 测试覆盖标准/扩展回环、完整载荷错误、只有 RX 没有 TX 完成、只有 TX 没有 RX、外部无 ACK、接收超时、取消、bus-off、过滤器错误、发送排队错误、停止清理错误和参数边界。
- 独立测试编译实际 HAL CAN 后端，使用私有 Zephyr API shim 验证帧转换、异步回调上下文、TX 池耗尽/停止回收、过滤器部分失败回滚、掩码/帧格式、旧 token 和状态映射。该 shim 不会进入真实固件。
- 尚未烧录实板，也未完成控制器实际内部回环、对端 ACK、波形、bus-off 故障注入和 USB/P10 实物互斥验证。主机通过不能代替这些步骤。
